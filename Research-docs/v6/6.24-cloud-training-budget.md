# Section 24: Cloud Training Budget — MVP vs Good-Quality Model

> **Added**: 2026-06-16
> **Question answered**: renting all GPU hardware in the cloud, how much money to train **our own** 4DGS-video generation model from multi-camera data + 4DGS ground-truth — for an MVP, and for a good-quality model.
> **Basis**: red-team-audited machine-time (§6.13), cloud prices (§6.5/§6.9), obtainable-data plan (§6.17), 2-GoPro capture (§6.21). All numbers are **estimates with the arithmetic shown** — this project runs a hallucination-audit discipline.

---

## TL;DR

| Tier | Cloud compute + data + storage + fitting | What you get |
|---|---|---|
| **MVP (adequate)** | **≈ $5,000 – 10,000** | Front faithful, plausible/temporally-stable back, works on your subjects + demo. Fine-tune of Wan-2.1-1.3B. |
| **Good-quality model** | **≈ $30,000 – 60,000** | Production-grade generation: fuller curriculum + more/broader data + more views + (optionally) a bigger 5B backbone + distillation. |

Excludes: legal/FTO (~$16–26K, **only for a commercial launch**, not the NC MVP — §6.7), your own time/salaries, and the 2-GoPro capture (hardware you already have → ~$0). Cheapest possible non-goal: **zero-training** Layer-0 (released weights + per-video 4DGS fit) ≈ **$0–500** cloud, but that is *not your own trained model* (§6.16).

---

## 24.1 Assumptions (all verifiable)

- **We fine-tune, not train from scratch.** Backbone = Wan-2.1-1.3B (Apache 2.0) + PRoPE (§8.1.1). Training from scratch would be the old $57K+ plan (§6.5); fine-tuning is far cheaper. Top quality may use **Wan-2.2-5B** (~4× compute/step).
- **Cloud GPU price (2026, §6.5/§6.9)**: H100 on-demand **~$2–3/hr** (use **$2.5**), spot ~$1.5; H200 ~$3.5; B200 ~$5.5. Cost scales with **GPU-hours**, independent of how many GPUs you rent in parallel (parallelism buys wall-clock, not total cost).
- **Data acquisition ≈ $0**: open surround datasets (PKU-DyMVHumans, CMU Panoptic, HUMBI, THuman/2K2K scans — §6.17/§21.8) download free; own capture uses your 2 GoPros. Money is spent only on **prep compute + storage + 4DGS-GT fitting**.
- **"Ready 4DGS" ground truth** = fit 4DGS on the open multi-camera scenes (gsplat, Apache) to supervise the generator — this is compute, folded into data-prep below.
- **Biggest uncertainty (§6.13 red-team)**: the paper's batch size is **unpublished** → a full replication is anywhere from **1,000–10,000 H100-hours** (a 10× swing). This is why every figure is a range, not a point.

## 24.2 Compute reference points (from §6.13, audited)

- Full Flex4DHuman replication (105k iters, 256²→512², V=16, 1.3B): floor **~583 H100-h** at ideal MFU; realistic (≈35% MFU) **~1,600 H100-h** for ONE successful full run.
- Reduced regime (our 2-frontal, humans-only, fewer iters, mostly 256²): **~300–600 H100-h** per successful run (≈ §6.13 S3 "faithful reduced" = 2–4 GPU-weeks on one RTX 6000 Pro × the ~0.55 H100-equivalence).
- You never get it right on run #1: budget **×3–4** for failed campaigns + ablations + hyperparameter search. This multiplier is the real cost driver, not the single-run number.

## 24.3 MVP budget (adequate quality)

| Item | Estimate | Basis |
|---|---|---|
| Successful reduced full-FT run (2-frontal, humans, ~40–60k iters) | 300–600 H100-h | §6.13 S3, reduced |
| × attempts/ablations (×3) | 900–1,800 H100-h | first-try never works |
| Stage-B LoRA adaptation on 5 subjects | 30–80 H100-h | small |
| VAE latent precompute (open datasets) | 50–150 H100-h | one-time |
| 4DGS-GT fitting on open scenes (gsplat) + demo clips | ~150 H100-h (~$0.5–1/clip) | §6.9/§6.16 |
| **Compute subtotal** | **~1,150–2,200 H100-h × $2.5 = $2,900–5,500** | |
| Cloud storage (5–10 TB datasets+latents+ckpts × 1–2 mo) | $300–1,500 | ~$20–100/TB-mo |
| Misc (dev instances, egress, optional distillation ~$500) | $500–1,000 | |
| **MVP TOTAL** | **≈ $4,000–8,000 → budget $5–10K** | |

Spot pricing (~$1.5/hr) can cut the compute ~40% → MVP as low as **~$3–4K** if you tolerate interruptions.

## 24.4 Good-quality model budget

Two paths — quality scales with backbone size, data breadth, and number of campaigns:

**(a) 1.3B backbone, FULL curriculum + full data (HUMBI + scans + more subjects) + V=16@512²**
| Item | Estimate |
|---|---|
| Full successful run | ~1,600 H100-h |
| × campaigns/ablations (×4) | ~6,400 H100-h × $2.5 = **~$16K** |
| Data (more capture, storage 3–6 mo, fitting at scale) | ~$5–10K |
| **Subtotal** | **~$20–30K** |

**(b) Wan-2.2-5B backbone (best quality) + full curriculum + HP search + distillation**
| Item | Estimate |
|---|---|
| Full run (5B ≈ 4× per step) | ~5,000–8,000 H100-h |
| × campaigns (×3–4) | ~18,000–28,000 H100-h × $2.5 = **~$45–70K** |
| Data + storage + fitting | ~$10–15K |
| **Subtotal** | **~$50–70K** (partly offset by spot) |

**Good-quality realistic range: ~$30–60K** (1.3B-full at the low end ~$25–35K; 5B for top quality ~$50–70K).

---

## 24.5 What moves the number (rank-ordered)

1. **Number of failed training campaigns** — each full campaign is real money; good data hygiene + the M0.5 PRoPE pre-gate (§6.14) + small pilots before full runs is the cheapest way to save thousands.
2. **Unpublished batch size** — up to 10× compute swing; only resolved by our own scaling test.
3. **Backbone: 1.3B vs 5B** — ~4× compute for the bigger model.
4. **Spot vs on-demand** — ~2× (spot ~$1.5 vs on-demand ~$3), at the cost of interruptions (needs the robust checkpoint/resume from §6.14/§21.8).
5. **Data breadth for the back** — adding HUMBI + scans (§21.8) improves quality with almost no extra *compute*, just storage — the cheapest quality lever.

## 24.6 Recommendation

- **Start with the MVP ($5–10K).** It proves the pipeline on real footage and validates demand before any big spend. Do the **zero-training Layer-0 demo first (~$0–500)** to de-risk the product hypothesis before spending the MVP budget at all.
- **Gate the good-quality spend on MVP results + demand signal** (waitlist/pre-orders, §6.12 kill-criteria). Only scale to 5B/full-curriculum ($30–60K) once the MVP shows the quality curve is worth it.
- **Reconciliation with prior docs**: §6.8's "~$10–20K fine-tune" and §6.9's "~$62–70K Track A MVP" were broader-scope (whole product incl. LRM/compression/ComfyUI R&D). *This* doc isolates the **training-a-model** slice on **cloud rental + obtainable data**, which is why the MVP training figure is lower (~$5–10K).
