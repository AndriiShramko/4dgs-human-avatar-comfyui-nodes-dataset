# Section 7: Legal Strategy and Clean-Room Design

> **Fact-check audit (2026-06-12):** 34 claims checked, 9 corrected, 3 unverifiable/likely hallucinated. Annotations inline. Key findings: both alternative body models (Anny, MHR) verified as real and Apache-2.0; however, Anny's SMPL-X-topology compatibility mode is **non-commercial only** — a legal red flag the original draft missed. The Inria license quote, gsplat performance figures, SMPL-X CC-BY scope, and the Anthropic/Ross case characterizations have been corrected against primary sources.

## Executive Summary

The v5 legal analysis is **directionally correct** but contains a critical gap: it treats the SMPL licensing problem as having no practical solution other than expensive Meshcapade licensing or abandoning parametric body models entirely. In reality, **two commercially viable, Apache 2.0 licensed alternatives emerged in late 2025**: Anny (NAVER Labs) and MHR (Meta). Both are commercially usable replacements for SMPL in feed-forward avatar generation pipelines (caveat: Anny's optional SMPL-X-topology mode is non-commercial only — see §7.1). The gsplat recommendation is confirmed as sound. Clean-Room Design methodology is validated but v5 fails to estimate the **real timeline cost** (+3-6 months to development) and required **organizational infrastructure** (3-team isolation protocol).

## SOTA Analysis 2025-2026

### 7.1 Anny: NAVER Labs Parametric Body Model (Apache 2.0)

Released in November 2025 (v0.1, 2025-11-05; paper arXiv:2511.03589), Anny is a comprehensive open-source alternative to SMPL:

**License**: Apache License 2.0 for the code and core model. [verified 2026-06-12 against repo] Asset provenance per the repo: MakeHuman community assets (CC0 1.0), SOMA-X (Apache 2.0), **SMPL-X-derived assets (non-commercial only)** — see caveat below.

**Technical capabilities**:
- Covers **full human lifespan**: infants to elderly in a single unified model [confirmed — NAVER Labs blog & paper]
- Interpretable controls: age, height, weight, muscle sliders [confirmed]
- Based on MakeHuman community anthropometric assets, calibrated with WHO population statistics (privacy-friendly — scan-free) [confirmed via NAVER Labs blog and arXiv:2511.03589; WHO calibration is described in the blog/paper, not the repo README]
- Competitive results on human mesh recovery benchmarks (per the Anny paper — self-reported, not independently benchmarked)
- v0.3 (2026-02-04) adds **SMPL-X topology compatibility**; v0.5 (2026-06-03) adds SOMA support [confirmed from repo release notes]

**GitHub**: https://github.com/naver/anny (active development, tutorials, interactive demo)

**⚠️ Critical legal caveat [fact-check 2026-06-12]**: per the Anny repo, the SMPL-X-topology interoperability mode is **limited to non-commercial use** (it relies on SMPL-X-derived assets under the MPI non-commercial license). The original claim that "existing SMPL-based pose estimation models can work with Anny's body representation without retraining" is therefore **not usable in a commercial product**. For commercial deployment, only Anny's native (MakeHuman-derived) topology and CC0/Apache assets may be used; SMPL-X-topology output must be excluded from the shipped pipeline.

### 7.2 MHR: Meta Momentum Human Rig (Apache 2.0)

Released in November 2025 (paper arXiv:2511.15586, submitted 2025-11-19), MHR is Meta's parametric 3D human body model:

**License**: Apache License 2.0 — full commercial freedom. [verified 2026-06-12: github.com/facebookresearch/MHR exists and is Apache-2.0]

**Technical capabilities** [all verified 2026-06-12 against repo README and paper]:
- 45 shape parameters (body identity: 20 body + 20 head + 5 hands)
- 204 pose/model parameters (articulation — joint angles and scaling; 127 joints)
- 72 facial expression parameters
- 7 levels of detail (LOD 0-6) for performance flexibility
- GPU-accelerated PyTorch implementation for real-time applications (>120 fps full-body animation on a desktop GPU per the paper); CPU solver via pymomentum also available

**GitHub**: https://github.com/facebookresearch/MHR

**Key advantage for our project**: LOD system allows using lightweight representation during training (fast iteration) and high-detail at inference (quality output). Facial expressions are included — SMPL requires separate SMPL-X for face/hands.

### 7.4 gsplat Legal Analysis (Confirmed)

gsplat (Nerfstudio project) under Apache License 2.0:

- **Section 2 (Grant of Copyright License)**: Perpetual, worldwide, irrevocable right to reproduce, distribute, and create derivative works
- **Section 3 (Grant of Patent License)**: Contributors grant perpetual patent license for any patents embodied in their contributions
- **Section 4 (Redistribution)**: Must retain copyright notices and NOTICE file; no obligation to open-source derivative works
- **No copyleft/viral requirements**: Unlike GPL, does not require opening proprietary code

**Technical validation**: gsplat provides packed sparse tensor mode (`packed=True`) critical for handling variable-length Gaussian sets, sparse gradient support (`sparse_grad`), N-dimensional feature rendering, and distributed multi-GPU rasterization. [fact-check 2026-06-12: these are parameters/features of the gsplat `rasterization()` API (docs.gsplat.studio); the repo README additionally confirms arbitrary batching over scenes and viewpoints. Performance claim per README: "up to 4x less GPU memory with up to 15% less time" vs the official implementation.]

### 7.5 Clean-Room Design: Realistic Assessment

**What Clean-Room protects against**:
- Copyright infringement claims (code copying)
- Derivative work claims (code modification)
- Trade secret misappropriation

**What Clean-Room does NOT protect against**:
- Patent infringement (independent creation is not a defense)
- Breach of Terms of Service (if team members signed academic licenses before joining)
- Inadvertent contamination (developer saw code on GitHub before the clean-room process started)

**Realistic timeline impact** (internal planning estimates — not industry benchmarks; actual durations depend on team size and module complexity):

| Clean-Room Activity | Duration (estimate) | Notes |
|-------------------|----------|-------|
| Specification Team: analyze papers → write math specs | 4-6 weeks | Per major module (attention, rasterizer, loss functions) |
| Legal review of specifications | 1-2 weeks | Per spec document |
| Implementation Team: code from specs | 6-10 weeks | Per major module |
| Verification and testing | 2-4 weeks | Functional equivalence testing |
| **Total per module** | **13-22 weeks** | |
| **Full pipeline (parallel modules)** | **4-6 months** | With 3-4 parallel module teams |

**Organizational requirements**:
- Physically separate development environments (separate Git repos, separate Slack channels)
- No cross-team code review between Specification and Implementation teams
- Legal audit trail: timestamped commits, specification sign-off documents
- Background checks: ensure Implementation Team members haven't previously worked with restricted code

## Critical Analysis

### Risk 1: Anny/MHR Ecosystem Maturity

SMPL has been the industry standard for 10+ years. Anny and MHR are 1-2 years old. Risks include:
- Fewer pre-trained pose estimation models compatible with Anny/MHR topology
- Less community support and debugging resources
- Potential breaking changes in early versions

**Mitigation**: ⚠️ [corrected 2026-06-12] Anny v0.3's SMPL-X topology compatibility is **non-commercial only** and cannot serve as a commercial mitigation — even internal R&D use inside a commercial program is gray-zone under MPI-style non-commercial terms and needs legal sign-off; it must never appear in the shipped product. Commercial mitigation must rely on Anny's native topology or MHR, plus retraining/fine-tuning of pose estimators against the chosen topology. MHR's PyTorch implementation follows standard skinning conventions.

### Risk 2: Patent Landscape Beyond SMPL

Even after removing SMPL, the 4DGS avatar pipeline may encounter other patents:
- Differentiable rendering patents (various holders)
- Attention mechanism patents in transformer architectures
- Body pose estimation method patents

**Mitigation**: Conduct a focused freedom-to-operate (FTO) search on core algorithmic components before MVP launch. Budget: ~$15,000-25,000 for a specialized IP attorney (rough estimate, not a quoted price — FTO costs vary widely by scope and jurisdiction).

### Risk 3: Clean-Room Process Failure

Common failure modes:
- Developer on Implementation Team googles a function name and finds the restricted repository
- Specification Team includes too-specific implementation details that mirror original code
- Time pressure leads to shortcuts (skipping legal review)

**Mitigation**: Strict browser monitoring on Implementation Team machines (block specific GitHub repos). Automated code similarity scanning (using tools like MOSS or JPlag) on every commit.

### Risk 4: Meta's MHR Future Licensing

Apache 2.0 is irrevocable — Meta cannot retroactively change the license for already-released code. However:
- Future versions of MHR could use a different license
- Meta could stop maintaining the project
- Patent landscape around Meta's body model research could evolve

**Mitigation**: Fork MHR at a specific version and maintain internally. Apache 2.0's irrevocable grant protects the forked version permanently.

**Module 1: Voxel-Aligned Transformer** (8-12 weeks)
- Spec from: VolSplat paper, 4DGT paper (math only)

- Spec from: VeGaS paper, DCT math textbooks
- Implementation: Pure tensor operations, well-understood math

**Module 3: GNN Dynamics Module** (6-8 weeks)
- Spec from: CloDS paper, GNN theory
- Implementation: PyTorch Geometric or custom message passing

**Module 4: Composite Loss Function** (2-3 weeks)

- Spec from: MEGA paper, P-4DGS paper
- Implementation: Custom codec, no reference code from MEGA repo

- Spec from: ComfyUI API documentation (GPL, but node API is public)
- Implementation: Custom node package, isolated from ComfyUI internals

## Open Questions

1. **Anny vs MHR head-to-head**: Which produces better results for our specific use case (studio rig, diverse subjects, 4K quality)? Requires A/B testing.
2. **Pose estimator compatibility**: Which open-source pose estimator works best with Anny/MHR topology? Candidates: ViTPose (Apache 2.0 — verified 2026-06-12) and 4DHumans [fact-check 2026-06-12: repo code is MIT, but it requires the SMPL neutral model downloaded under MPI's non-commercial terms — NOT usable commercially as-is; would need re-targeting to Anny/MHR].
3. **Diffusion teacher licensing**: If we use Stable Diffusion XL as the diffusion teacher during training, do the generated intermediate latents "contaminate" our model weights? Legal opinion needed.
4. **ComfyUI GPL boundary**: ComfyUI itself is GPL-3.0. Our custom nodes are separate packages loaded at runtime. Does this constitute a "derivative work"? Standard legal opinion says no (plugins are not derivatives), but should be confirmed.
5. **International patent landscape**: The FTO search should cover US, EU, and Asian patent offices. SMPL patent (US10395411B2) may have equivalents in other jurisdictions.
