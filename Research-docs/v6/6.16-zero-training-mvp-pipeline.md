## Executive Summary

**The goal is faithful reconstruction of REAL VIDEO. The zero-training answer splits by how many cameras you shot:**

- **2-8 synchronized real cameras → faithful 4DGS, works THIS WEEK, no training.** Per-video 4DGS optimization (gsplat + Shape-of-Motion / MoSca / 4DGaussians / FreeTimeGS-class, all MIT/ungated) fits the *actual* performance from multiple real viewpoints. Because the cameras saw the subject from multiple angles, the result is faithful **all the way around** — real motion, real garment dynamics, real appearance. This is the strongest real-video path the moment a mini-rig exists, and it runs comfortably on 96 GB. Runtime minutes-to-tens-of-minutes/clip [estimate].
- **Monocular real video → faithful where the camera saw it, inferred where it didn't.** Per-video optimization for a single view (Shape-of-Motion / MoSca / Dynamic Gaussian Marbles for general scenes; **ExAvatar / GART** for human-specific, both MIT, faithful to *your* subject) reconstructs the visible side of the real performance now, no training. The physical limit is unavoidable: **a single camera never observes the back**, so a full-360 result must *infer* the unseen side — no tool changes that. Making that inference look right and temporally stable is exactly what the Layer-1 learned view-generator (§6.19 / §6.8) adds.

**Honest verdict.** There is **no released, ungated, single-GPU model that takes a monocular video and returns a faithful 4DGS human in one feed-forward pass** — the methods that come closest (MV-Performer, Diffuman4D, Flex4DHuman) are exactly the DNA-Rendering-trained / unlicensed / unreleased ones we avoid (§16.4). So real-video reconstruction this week = **per-video optimization** (faithful to what was filmed; multi-cam = faithful 360°, monocular = faithful front + inferred back). LHM-style photo→avatar is explicitly NOT this and is excluded from the product path.

**Top obtainability caveat.** Every *human-faithful* multi-view generator is compromised: **MV-Performer** weights are on OneDrive with **no LICENSE file [A]** and trained on **MVHumanNet (request-form) + DNA-Rendering (gated) [B]**; **Diffuman4D** is DNA-Rendering-provenance and needs **4 synchronized views + Sapiens (CC BY-NC) [A]**; **Flex4DHuman** code is **unreleased [A]**. So the *clean* this-week path trades faithfulness for obtainability: **LHM-class feed-forward (best look, hallucinated 4D)** or **per-video optimization (faithful geometry, no human prior, slow)**.

## 16.2 Recommended Chained Pipeline for 1×96 GB (this week, zero training)

> Reordered per the owner correction: the product is **faithful reconstruction of real video**, so per-video optimization is the PRIMARY path. Photo→avatar (LHM) is NOT the product — see the excluded note at the end.

### Path A — Faithful real-video → 4DGS (PRIMARY, ungated)
```
Real video:  monocular  OR  2–8 synchronized cameras
  → [ours, Apache] ComfyUI prep: matting (MatAnyone2/BiRefNet), masks, stabilization
  → camera/depth front-end: MegaSaM (Apache code) or MonST3R  [mono];
       known extrinsics/calibration  [multi-cam]
  → per-video 4DGS optimization:
       general scene  → [MIT] Shape-of-Motion / MoSca  (or Instant4D ~5 min [B])
       human-specific → [MIT] ExAvatar / GART  (faithful to your subject)
       fitting backend → gsplat (Apache) + MCMC
  → [ours, Apache] Load/Render/Animate4DGS nodes + web viewer
```
- **Why this is the product**: it fits Gaussians to *your actual pixels*, so geometry, motion, clothing and appearance are faithful to the real performance — not a puppet from a prior.
- **Multi-cam (2–8) is the strong case**: more real viewpoints → faithful all the way around (real back, not invented). This is the moment the mini-rig/rig pays off; feed synchronized views as extra cameras.
- **Monocular case**: faithful on the side the camera saw; the back is physically unobserved → either accept an incomplete/inferred back, or densify (Path B) / fine-tune (§6.19 Layer 1).
- **Cost**: minutes (Instant4D ~5 min [B]) to longer per-video optimization (Shape-of-Motion — no published single number, **measure week 1**). VRAM is not the constraint on 96 GB; compute time is.

### Path B — Optional view-densification before fitting (experimental, license-flagged)
- **DimensionX** (open, ungated) to hallucinate orbit views of a monocular clip before fitting — **but general-scene, identity drifts; CogVideoX base license is custom-not-Apache**. Research toy, not core.
- **MV-Performer / Diffuman4D**: best human multi-view quality, but **blocked** (no license / DNA-Rendering provenance / Sapiens-NC / needs 4 cams). Research-use-only, never the shippable path.

### Excluded — photo→avatar (NOT the product)
**LHM / IDOL / AniGS / PSHuman** turn a single image into a rigged 3DGS puppet. That is avatar *generation*, not reconstruction of a real performance, so it is **out of the product path** per the owner directive. Keep only as an optional "stylized avatar" side-feature if ever wanted — it does not reproduce the actual person's real motion/garment dynamics from their video.

**Fitting backend (all paths): gsplat (Apache) + MCMC + Gaussian budget.** Avoid Inria-NC `diff-gaussian-rasterization` (pulled by 4DGaussians/Deformable-3DGS) to keep the stack clean even at NC stage. FreeTimeGS works but is **AGPL** — fine for NC, flag it.

## 16.3 96 GB-specific notes
- Per-video optimizers (Shape-of-Motion/Instant4D/MoSca/ExAvatar/GART) are compute-time-bound, not VRAM-bound on this card; 96 GB removes any tiling and lets you fit longer clips / more cameras / higher Gaussian budgets at once. This is the real-video reconstruction path — VRAM headroom directly buys fidelity and clip length.
- More real cameras (2–8) → more constraints per optimization → faithful 360° without hallucination; 96 GB easily holds the multi-view set in memory.

## 16.4 What Zero-Training CANNOT Deliver (hand-off to §6.13 / synthesis)
1. **Faithful 4D *human* from arbitrary monocular video in one pass.** The only models built for it (MV-Performer, Diffuman4D, Flex4DHuman) are precisely the gated/unlicensed/unreleased ones. Closing this needs the **light fine-tune of Wan-2.1-1.3B on clean/own data** (§6.8/§6.9 plan) — *that* is where training re-enters.
2. **Correct occluded/back-side appearance.** LHM/DimensionX hallucinate it; faithful back needs either multi-cam capture (Path B with 4–8 cams) or a generative prior fine-tuned on clean multi-view data.
3. **True garment/secondary dynamics** beyond rigid SMPL-X reposing — feed-forward avatars don't capture it; per-video opt captures only what the camera saw.
4. **Temporal stability across generated views** — any diffusion-densified path flickers; documented as a Track-A regularizer task, not solvable zero-shot.

→ The bridge: ship Path A/B now as the NC MVP, and route the "faithful human 4D" gap to the **Wan-1.3B fine-tune on self-rendered UE5 / owned multicam data** (§6.9 R1/R2), which needs **no gated dataset**.
