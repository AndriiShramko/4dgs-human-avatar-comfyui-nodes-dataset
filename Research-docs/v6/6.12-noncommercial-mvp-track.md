## Executive Summary

1. **A monocular → multi-view → 4DGS pipeline is runnable today from pre-trained parts.** **MV-Performer** (SIGGRAPH Asia 2025) is the only released model that takes a *single monocular* full-body video and generates synchronized 360° novel-view videos — built on Wan2.1-T2V-1.3B (Apache 2.0), code + checkpoints public. **Critical blocker: the repo has NO license file** [A — file listing checked], so by default all rights are reserved; we must email the authors before any public demo that depends on it (cheap, week-1 kill-criterion).
2. **Diffuman4D is the licensing surprise of this audit**: its code repo shows **Apache-2.0** [A — repo page] and its weights are tagged **openrail++** on HF [B]. The CreativeML Open RAIL++-M text (read directly [A]) **permits use, redistribution, and even commercial use**, subject only to Attachment-A behavioral use restrictions and license pass-through. The non-commercial constraint comes from *data provenance* (trained on gated, research-only DNA-Rendering), not from the license text — so a public NC demo and weight redistribution are clearly permitted; commercial use is a provenance risk we decline by policy. Catch: it needs **4 synchronized input views** (not monocular) and its preprocessing depends on **Sapiens (CC BY-NC 4.0** [A]).
3. **The 4DGS fitting stage is license-clean everywhere**: gsplat (Apache 2.0, §9) and Hybrid 3D-4D GS (**MIT** [A]) are unrestricted; Instant4D code is public but has **no license file** [A — file listing].
4. **Recommended stack**: monocular video → our existing ComfyUI preprocessing nodes (matting/stabilization) + Sapiens/MoGe/Pi3 prep → **MV-Performer** multi-view generation (4-view primary; optional **Diffuman4D** densification when the user has 4 cameras) → **gsplat (MCMC) + Hybrid 3D-4DGS-style static/dynamic split** per-clip fit → our Load/Render/Animate4DGS nodes. Everything we write is Apache 2.0; all NC weights are downloaded by the end user from original hosts (standard ComfyUI practice — we never redistribute them).
5. **Time/cost to public demo: 3-5 weeks, ≈$700-1,600 [estimate]** — GPU rental for integration + a 10-video benchmark, a hosted demo/waitlist page, zero training. Single RTX 4090 suffices for the 1.3B-based generation stage; Diffuman4D timings are published only for A100 (~2 min per 48-frame sequence [B]).
6. **What it buys**: demand signal (waitlist), end-to-end pipeline debugging on real dirty videos, ComfyUI-community standing, and a public artifact one day after Flex4DHuman-class attention peaks. **What it does not buy**: any weights, outputs, or synthetic data usable in commercial Track A — knowledge transfers, artifacts do not.

## 12.2 Recommended Track C Pipeline (concrete stack)

```
User monocular video (5-10 s, static camera, full body)
  → [ours, Apache] ComfyUI prep: SeC/MatAnyone2 matting, stabilization, crop/resize
  → [NC prep] Sapiens 2D keypoints (CC BY-NC) · MoGe depth (MIT code) · Pi3 camera/geometry
  → [NC core] MV-Performer: synchronized novel-view videos around the actor (Wan2.1-1.3B base)
      (optional, 4-camera input instead: Diffuman4D → dense 1024p views)
  → [Apache/MIT] per-clip 4DGS fit: gsplat + MCMC + Gaussian budget + 3D/4D static-dynamic split
  → [ours, Apache] Load4DGS / Render4DGS / Animate4DGS ComfyUI nodes + web viewer export
```

**Hardware envelope (single RTX 4090, 24 GB)** — all numbers below are **[estimate]** unless sourced:
- MV-Performer generation: Wan2.1-1.3B inference fits consumer 24 GB (verified class result: FastWan 1.3B runs a 5-s 480p clip with 2.8 s denoising on a 4090, §9.2 [A]); undistilled multi-view generation of 4-8 views ≈ **10-40 min/clip** [estimate — no published 4090 figure; measure in week 1]. TeaCache (~2×, training-free, §9.2) applies.
- Diffuman4D (optional path): ~2 min per 48-frame sequence **on A100** [B — paper via search snippet]; VRAM on 4090 unverified — their README offers single-GPU `demo_4d_tiny` configs [A]; budget A100 rental hours for this path ($1.5-2.5/hr).
- 4DGS fit: 12 min/10-s clip (Hybrid 3D-4DGS, published, different GPU [B]); with gsplat MCMC + budget on 4090 ≈ **10-30 min/clip** [estimate].
- **Total ≈ 30-70 min per avatar clip on one 4090** [estimate]; rented 4090 at $0.30-0.70/hr → **<$1/clip** [estimate].

**Glue code to write (ours, Apache 2.0)**: MV-Performer/Diffuman4D wrapper nodes (subprocess or bundled pipeline), prep-format converters (nerfstudio cameras, skeleton maps), gsplat fitting node with budget/MCMC presets, .ply/.splat export + web viewer embed, one-click "download upstream weights from original hosts" script (we never mirror NC weights), demo workflow JSONs.

## 12.3 License Layering & Firewall vs Track A

**Artifact map of the Track C release:**

| Artifact | License | Distribution |
|---|---|---|
| Our ComfyUI nodes, glue, workflows, docs | **Apache 2.0 (ours)** | Our repo |
| MV-Performer code/ckpt, Diffuman4D weights, Sapiens, SHARP weights | Their licenses (none/OpenRAIL++/CC BY-NC/Apple Research) | **Never bundled** — user-side download from original hosts via our script |
| Example outputs / gallery clips | Released by us as **CC BY-NC 4.0** | Repo + site |
| Benchmark data (DNA-Rendering-derived, Human4DiT etc.) | Gated/NC | **Link only, never copied** |

- **Our nodes are not "infected" by NC weights.** A license on model weights governs the weights artifact; independently written code that loads them at runtime is a separate copyrighted work (same legal structure as every Apache-licensed ComfyUI node pack that loads OpenRAIL SD weights). We keep our code Apache 2.0. (ComfyUI itself is GPL-3.0; custom node packs are conventionally separately licensed — unchanged from our existing 72-node practice.)
- **Repo labeling**: top-of-README banner — *"Research preview. This pipeline depends on third-party models with research/non-commercial and use-restricted licenses (see LICENSES-THIRD-PARTY.md). Do not use outputs commercially. Our own code is Apache-2.0."* Plus per-component license table and the OpenRAIL++ Attachment-A restrictions reproduced verbatim (pass-through obligation).
- **Firewall vs commercial Track A (hard rules)**: (1) separate repo + separate storage; (2) no Track C weights, LoRAs, or fine-tunes ever loaded in Track A infrastructure; (3) **no synthetic data generated by Track C models enters commercial training** — not even as pseudo-labels or eval-set curation; (4) Track A clean-room spec team may read Track C *measurements and findings* (flicker stats, UX learnings, failure taxonomies) — these are facts/knowledge, not copyrightable artifacts; (5) team members who read MV-Performer/Diffuman4D *code* stay on the §6.7 spec side of the Track A clean-room, not the implementation side.

## 12.4 What Track C Buys / Does Not Buy

**Buys**: (a) the §8.5 demand kill-criterion executed for <$2K — public demo + waitlist measures willingness-to-wait before the $62-70K Track A spend; (b) every integration lesson of the exact Track A Quality-Mode shape (prep → multi-view diffusion → 4DGS fit → nodes) on real user videos; (c) flicker/quality baselines to beat; (d) ComfyUI community presence and a citable open artifact; (e) recruiting/partner conversations anchored on a working thing.

**Does not buy**: (a) any commercially usable weights — MV-Performer (unlicensed), Sapiens (NC), and our policy on Diffuman4D all block it; (b) training data — outputs are presumed derivative of NC-trained models; (c) Fast-Mode (<3 s) evidence — Track C is minutes-per-clip by construction; (d) brand permanence — Track C must be explicitly positioned as a research preview so the later commercial release is not judged by its latency.
