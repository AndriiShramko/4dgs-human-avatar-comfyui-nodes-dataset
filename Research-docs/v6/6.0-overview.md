# 4DGS Avatar Generator — MVP Architectural Plan v6

> **Version**: 6.0 — Critical Audit & Corrected Architecture  
> **Date**: March 2026  
> **Status**: Research-validated plan ready for implementation team  

> **Fact-check audit (2026-06-12):** All sections 6.1-6.7 were audited claim-by-claim against primary sources by a 7-agent verification team. Every cited paper was verified to exist; corrections and inline annotations are in each section file. Key corrections affecting this overview: (1) MEGA compression is 161→20 params, not 17; (2) the "5-15 dB occluded-region PSNR gap" was unsourced — documented sparse-view generalization gap is ~6 dB; (3) B200 2026 rental prices (~$4-6/hr) make per-run cost roughly comparable to H100 — the H100+FP8 choice now rests on FP8 maturity, not price; (4) Anny's SMPL-X-compatibility mode is **non-commercial only** — production must use Anny's native topology; (5) data filtering stages compound to ~84% reduction, not 65-75%; (6) the 10-20 MB/10s compression target is our extrapolation, not a published result. See also [Section 8](6.8-flex4dhuman-analysis.md) — analysis of new research source Flex4DHuman (UW + World Labs) added 2026-06-12.

## Project Overview

We are building an **MVP feed-forward model** for generating 360-degree photorealistic 4D Gaussian Splatting (4DGS) avatars from sparse camera views (1-3 cameras). The system must generate a complete animated avatar in under 3 seconds, renderable at 60+ FPS on consumer GPUs (RTX 4090, 24 GB VRAM), and deployable as ComfyUI nodes.

**Training data**: Proprietary 90-camera studio rig, 4K resolution, 60 FPS, hardware-synchronized. Each 10-second capture session produces ~54,000 frames.

---

## v5 → v6 Corrections Summary

This v6 plan is the result of a critical audit of 12 v5 research documents. The audit identified **7 significant overstatements, 3 critical gaps, and 2 new commercially viable alternatives** that materially change the architecture. Key corrections:

| Area | v5 Assumption | v6 Correction | Impact |
|------|--------------|---------------|--------|
| Loss functions | Chamfer Distance absolutely impossible | Near-linear approximate algorithms exist; still impractical for training but not "impossible" | Changes reasoning, not conclusion |
| Sparse-view strategy | Diffusion at inference = dead end | 1-step diffusion and hybrid feed-forward+refinement achieve near-real-time | **Architecture change**: add refinement stage |
| LRM quality | Single-pass LRM produces flawless back regions | Pure feed-forward LRMs produce blurry occluded regions | **Architecture change**: mandatory refinement |
| Kinematics | DCT/polynomial trajectories sufficient for all motion | DCT fails for loose clothing, hair dynamics | **Architecture change**: add physics-aware GNN module |
| Data preprocessing | Diagonal FIM is optimal | Diagonal FIM questionable for heterogeneous parameters; Squisher (free from Adam) is better | Simplifies pipeline |
| Hardware | Must use Blackwell B200 + NVFP4 | NVFP4 has convergence issues; H100+FP8 is safer (2026 price check: per-run cost roughly comparable to B200 — decision driven by FP8 maturity, not price) | **Risk reduction**; budget ~$57K |
| Body model | SMPL blocked, no alternatives | Anny (Apache 2.0) and MHR (Apache 2.0) are drop-in replacements | **Risk elimination** |

## Section Breakdown

### [Section 1: Loss Functions and Graph Matching](6.1-loss-functions.md)
**Key decision**: Composite rendering loss (L1 + LPIPS + DISTS) with depth/normal priors. No point-cloud matching in training loop.

### [Section 2: Sparse-View Generation](6.2-sparse-view.md)
**Key decision**: Two-stage hybrid — voxel-aligned LRM base (~0.5s) + 1-step diffusion refinement (~1-2s). Total: <3s.

### [Section 3: Kinematics and Temporal Consistency](6.3-kinematics.md)
**Key decision**: Tiered motion — static (3D) / skeletal (DCT-12) / dynamic (physics-aware GNN). Soft learned segmentation masks.

### [Section 4: Data Preprocessing](6.4-data-preprocessing.md)
**Key decision**: Multi-stage filtering — geometric diversity → temporal subsampling → Squisher-style gradient informativeness (near-free from Adam, requires per-view logging). Progressive schedule: stages compound to up to ~84% reduction; start conservative.

### [Section 5: Hardware Economics](6.5-hardware-economics.md)
**Key decision**: MVP on H100/H200 + FP8. Optional B200 + NVFP4 migration for production scaling. Estimated training cost: ~$57K.

### [Section 6: Compression and Deployment](6.6-compression-deploy.md)
**Key decision**: MEGA DC-AC (161→20 params) + opacity entropy pruning + custom temporal layer inspired by P-4DGS. Target: ~10-20 MB per 10s clip (our extrapolation, not a published result).

### [Section 7: Legal Strategy](6.7-legal-strategy.md)
**Key decision**: MHR (Apache 2.0) as body model, gsplat (Apache 2.0) as rasterizer, Clean-Room Design for transformer code. FTO search budget: ~$16K. ⚠️ Anny's SMPL-X-compat mode is non-commercial — native topology only in production.

### [Section 8: Flex4DHuman Analysis & Integration (New Research Source)](6.8-flex4dhuman-analysis.md)
**Added 2026-06-12**: UW + World Labs released Flex4DHuman (arXiv 2606.13655) — monocular → dense multi-view video diffusion (Wan 2.1 1.3B, Apache 2.0) → 4DGS. Directly addresses our Risk #1 (occluded-region hallucination). Recommendation: adopt as offline "Quality Mode" track; the <3s feed-forward path remains the v2 "Fast Mode".

### [Section 9: Acceleration & Cost Reduction — Track A](6.9-acceleration-and-cost-reduction.md)
**Added 2026-06-12**: Verified optimizations for the independent open-source pipeline: LoRA-first fine-tune (ReCamMaster precedent on the same backbone), few-step distillation (FastWan, Apache 2.0; own distill ~$300-500), 10-30x faster per-clip 4DGS fitting (Hybrid 3D-4D GS: 12 min vs 5.5 h; Instant4D closes the moving-camera gap). Revised Track A MVP budget: **~$62-70K** (from $121K), ~1-3 min per avatar.

### [Section 10: Training-Data Strategy](6.10-data-strategy.md)
**Added 2026-06-12**: License-verified path to commercially clean data before the rig exists: $0-license synthetic stack (MakeHuman CC0 + Anny Apache + CMU mocap + Poly Haven CC0 + Rocketbox MIT — a clean replication of the BEDLAM recipe) + 8-12 camera consumer rig with own ML-training releases. Total ~$8-15K. RenderPeople/MetaHuman/Mixamo verified as ML-training-blocked by default.

### [Section 11: Track B — Gracia AI Collaboration](6.11-gracia-collaboration-track.md)
**Added 2026-06-12**: Partner track — Gracia's optimized 4DGS reconstructions as distillation targets for our generator. Verified company profile, pilot deal design (barter + partner-rate fee, model-rights clause), strict IP firewall: **Track A (open-source) trains only on our own data and continues unconditionally regardless of Track B**.

### [Section 12: Track C — Non-Commercial MVP](6.12-noncommercial-mvp-track.md)
**Added 2026-06-12** (owner decision): a fast/cheap **non-commercial** open demo assembled from released NC weights (MV-Performer monocular→360° core; Diffuman4D 4-view quality path) + clean Apache fitting (gsplat) + our ComfyUI nodes. Zero training; ~3-5 weeks, ≈$700-1,600 to public demo. Purpose: demand validation + community traction. Hard firewall: NC weights/data never touch commercial training (Tracks A/B).

### [Section 13: Single-GPU NC Training Plan (RTX 6000 Pro)](6.13-single-gpu-nc-training-plan.md)
**Added 2026-06-12, red-team audited 2026-06-16**: machine-time to train our OWN NC model (Flex4DHuman-style, Wan 2.1 1.3B + PRoPE) on one free RTX 6000 Pro Blackwell (96GB). Three scenarios: **S1** LoRA smoke ~1 GPU-day / ~1 wk; **S2 (recommended)** hybrid LoRA→full-FT ~7-14 GPU-days / **~5-8 wk calendar**, −2..−4 dB vs paper; **S3** faithful reduced full-FT ~2-4 GPU-wks / ~2-3.5 mo. The 96GB VRAM enables full-FT impossible on 24-48GB cards. ⚠️ **Hard blocker: DNA-Rendering data needs institutional license** — file request day-0; synthetic/BEDLAM fallback adds 3-6 wk + domain-gap penalty.

### [Section 14: Goal-Mode Agent Team Plan](6.14-goal-mode-agent-team-plan.md)
**Added 2026-06-12, red-team audited 2026-06-16**: how a 6-agent team builds the NC MVP autonomously on the workstation. Roster, milestones M0-M6 with numeric acceptance gates (+M0.5 PRoPE-correctness pre-gate, +M1 data-license two-branch), single-GPU lock discipline, restart-from-manifest, no-self-grading rule. Owner-gates: data-license acceptance (M1) and publishing (M6).

### [Section 15: World Tracing Analysis (New Research Source)](6.15-world-tracing-analysis.md)
**Added 2026-06-16**: World Tracing (World Labs + UIUC, arXiv 2606.13652) — diffusion model predicting stacked per-pixel camera-space XYZ maps (visible + occluded layers). License **CC BY-NC-ND 4.0** (non-commercial + no-derivatives) → NC track only. Useful as occlusion-aware geometry prior for 4DGS init / back-side hole-filling (Risk #1). Does NOT close our moving-camera SE(3) gap (VGGT/MegaSaM remain the front-end); sibling work "TrackingWorld" (arXiv 2512.08358) addressed in §6.18.

### Sections 16-19: "Buildable on one RTX 6000 Pro" research round (added 2026-06-16)
Owner directive: drop all institutionally-gated data; deliver a plan realizable on ONE RTX 6000 Pro (96 GB) with solo-obtainable models/data.
- **[§16 Zero-Training MVP](6.16-zero-training-mvp-pipeline.md)** — runs this week, no training: LHM (Apache, ungated) + per-video optimization; honest quality limits.
- **[§17 Obtainable Data](6.17-obtainable-data-plan.md)** — ungated replacements for DNA-Rendering: CMU Panoptic (open), AIST++ (CC BY), PKU-DyMVHumans (click-through, dense multi-cam) + synthetic. Volume clears the single-GPU fine-tune floor.
- **[§18 Frontier + Camera](6.18-frontier-and-camera-frontend.md)** — newest releases (Forge4D, NoPo4D, TrackingWorld); moving-camera front-end MegaSaM (NC) / VGGT-1B-Commercial.
- **[§19 ★ Buildable MVP synthesis](6.19-buildable-mvp-synthesis.md)** — the actionable plan: Layer 0 (this-week zero-training demo) → Layer 1 (light Wan-1.3B+PRoPE fine-tune on obtainable data — §6.13 S2, now UNBLOCKED) → Layer 2 (watch Forge4D/NoPo4D). **The §6.13 DNA-Rendering blocker is resolved for the NC track.**
