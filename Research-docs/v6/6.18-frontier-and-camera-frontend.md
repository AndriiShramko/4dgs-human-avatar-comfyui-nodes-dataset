## Executive Summary

**Top-3 newest findings (post-Dec-2025 emphasis):**

1. **TrackingWorld** (arXiv **2512.08358**, NeurIPS 2025, IGL-HKUST) — the resolution of the §6.15 follow-up flag. It is **NOT** World Tracing; it is a *world-centric monocular 3D tracking* system that **estimates camera poses and disentangles camera motion from dynamic-object motion** for almost-all-pixels, from a single in-the-wild video. **Code + weights released, MIT license** [V]. This directly targets our moving-camera gap — but it is an *optimization/pipeline* stack chaining many foundation models (UniDepth, CoTracker, DEVA, Grounded-SAM-2, Uni4D, + an OpenAI/GPT preprocessing call), so its real-world commercial usability depends on that dependency chain, not the MIT wrapper. [V]
2. **Forge4D** (arXiv **2509.24209**, ZJU) — **feed-forward 4D *human* reconstruction from uncalibrated sparse-view video**, the closest released analogue to our Quality-Mode pipeline shape. Code **Apache-2.0**, inference released, runs on a 24 GB GPU; but trained on **DNA-Rendering** (NC-provenance) and bundles the non-commercial 3DGS rasterizer license — so **weights are NC**, architecture is the value. [V]
3. **NoPo4D** (arXiv **2605.22190**, May 2026, ETH/Pollefeys et al.) — first **feed-forward dynamic Gaussians from *unposed* multi-view video** (jointly solves dynamics + multi-view + unknown poses in one pass). Code/weights "will be released" — **not yet public** as of 2026-06-16 [V/U]. Watch-item; would collapse pose-estimation + reconstruction into one network if released permissively. Also newly surfaced: **Lyra 2.0** (NVIDIA, Apr 2026, monocular video → 4D-GS via video-diffusion self-distillation, Apache-2.0 code / research-only weights) and **ShapeGaussian** (arXiv 2602.05572, Feb 2026, template-free monocular 4D human, optimization-based).

**Recommended moving-camera front-end:** **VGGT-1B-Commercial** (Meta) for the *commercial* tracks A/B — it is the only front-end here with an explicit **commercial license** (commercial OK, no-military), feed-forward, single-GPU, seconds per clip [V]. For the **NC-MVP track**, **MegaSaM** (Apache-2.0 code, CC-BY materials, built for *casual dynamic* in-the-wild video — exactly our input) is the better-quality choice for moving cameras [V]; **TrackingWorld** is the richest option when full static/dynamic 3D track disentanglement is wanted (NC in practice via its dependency chain). MASt3R-SLAM / DUSt3R / MASt3R / MonST3R / CUT3R / π³ are all **NC** (dataset-poisoned or NC-weights) and route to the NC track only.

## 18.3 TrackingWorld dependency-license chain (why MIT ≠ commercial)

TrackingWorld's MIT license covers only its glue. Inference invokes (verified from README [V]): **UniDepth**, **CoTracker V3**, **DEVA**, **Grounded-SAM-2**, **Recognize-Anything (RAM)**, **DELTA/DenseTrack3D**, **Uni4D** backbone, **and an OpenAI/GPT API call** for preprocessing. Several of these carry research/NC or non-Apache terms, and the GPT-API dependency is an external paid service. **Consequence**: treat TrackingWorld as a powerful **NC-track / research** front-end and back-side-disentanglement tool; do not assume the MIT wrapper makes the pipeline commercially clean. For a commercial path we either (a) use VGGT-1B-Commercial, or (b) re-implement the pose stage on permissive components.

## 18.4 Integration Recommendation

- **Commercial Tracks A/B (mono path):** **VGGT-1B-Commercial** as the camera-pose / point-map front-end. Single forward pass, seconds, single GPU, the only explicitly-commercial option here. Feed its per-frame extrinsics into the PRoPE/SE(3) conditioning band (§8.1.1). Caveat: gated form acceptance + no-military clause; include in the IP review already budgeted (§6.7). For *static-camera* clips, VGGT is overkill but harmless.
- **NC-MVP Track (§6.12/6.13):** **MegaSaM** for moving-camera casual video (Apache code, dynamic-scene design, 4090-class), **+ TrackingWorld** when full static/dynamic 3D-track disentanglement or per-pixel motion is needed (offline preprocessing node, NC). These complement World Tracing's geometry prior (§6.15) — MegaSaM/TrackingWorld give *extrinsics*, World Tracing gives *occluded geometry*; different outputs.
- **Watch-items (no action yet):** **NoPo4D** (if released permissively → collapses pose+recon into one feed-forward net, a Fast-Mode candidate); **Forge4D** weights at release (architecture study only — NC provenance bars the weights from commercial use); **Lyra 2.0** distillation recipe as inspiration for our Fast-Mode self-distillation.

## 18.5 What changes vs our current plan

1. **The §8.3.6 / §6.15 moving-camera gap now has a concrete, verified answer for both tracks** — VGGT-1B-Commercial (commercial) and MegaSaM (NC), with TrackingWorld as the richest NC option. The gap moves from "open" to "front-end selected, integration-test pending."
2. **TrackingWorld follow-up from §6.15 line 61/109 is RESOLVED**: it is a real, MIT-wrapped, camera-pose-producing system (not World Tracing), but commercially gated by its dependency chain → NC-track tool.
3. **Forge4D validates the feed-forward human-4D direction** Flex4DHuman punts to v2 — a released Apache-coded reference (weights NC) we can study in the §6.7 clean-room spec lane.
4. **No newer source supersedes Flex4DHuman** for the monocular-human quality path; our Quality-Mode plan (§8.3) stands. NoPo4D is the only release that could change the Fast-Mode design if it lands permissively.
5. **96 GB headroom**: every front-end here fits well under 96 GB (all were validated on 24-80 GB), so the RTX 6000 Pro is not a constraint for the front-end stage; it is a comfort margin for running pose-estimator + diffusion + 4DGS-fit without offloading.
