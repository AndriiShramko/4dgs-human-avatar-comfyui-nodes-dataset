## Executive Summary

**The blocker that stalled §6.13 is removed.** §6.13's "hard day-0 blocker" was DNA-Rendering's institutional gate. §6.17 found license-clean, ungated, solo-downloadable replacements that fill the same dense-multi-camera role, so the single-GPU training plan is now executable end-to-end on the owner's machine with **zero institutionally-gated dependencies**.

There are **three layers**, deployable in order, each useful on its own:

- **Layer 0 — this week, ZERO training.** Chain released ungated models on the 96 GB card to get a working demo immediately: **LHM** (Apache-2.0, ungated weights) for an instant single-image avatar look, and **per-video optimization** (Shape-of-Motion / MoSca / Instant4D, MIT/ungated) for faithful dynamic reconstruction from the 2-8 camera path. Camera poses for in-the-wild monocular via **MegaSaM** (Apache code). Fit/visualize on **gsplat** (Apache) + our ComfyUI nodes. *Honest limit: LHM hallucinates the back and is rigid-reposed; per-video opt is faithful but slow and weak from a single view.*
- **Layer 1 — weeks 2-8, the light fine-tune (§6.13 S2, now unblocked).** Replicate the Flex4DHuman-style Wan-2.1-1.3B + PRoPE multi-view generator (spec in §8.1.1), fine-tuned on **obtainable** data (§6.17): PKU-DyMVHumans + CMU Panoptic + AIST++ + our self-rendered synthetic. This closes the one gap Layer 0 can't fill: *faithful* dynamic 4DGS human from monocular/sparse input.
- **Layer 2 — watch/upgrade.** **Forge4D** (Apache code / NC weights) as an alternative feed-forward 4D-human architecture; **NoPo4D** (code unreleased — watch); **VGGT-1B-Commercial** as the camera front-end if/when this graduates to a commercial product.

**Bottom line for the owner:** a usable demo runs on your machine THIS WEEK with zero training; a *faithful* monocular→4DGS-human model is ~5-8 calendar weeks of single-GPU work (per red-team-audited §6.13 S2) on data you can actually download — no university, no PI, no Shanghai AI Lab approval.

## 19.1 Layer 0 — Zero-Training Demo (runs now on 96 GB)

| Input path | Stack | License | Faithfulness | Runtime (1×96 GB) |
|---|---|---|---|---|
| Monocular, "good look" | **LHM-1B** (single frame → animatable 3DGS, driven by pose extracted from clip) → per-frame 3DGS = 4DGS | Apache-2.0, weights ungated (`3DAIGC/LHM-1B-HF`) [verified §6.16] | Front great; back hallucinated; rigid SMPL-X repose; no garment dynamics | ~1.4-6.6 s/frame-class on 24 GB → trivial headroom |
| 2-8 cameras, "faithful" | **Per-video optimization** (Shape-of-Motion / MoSca / Instant4D) on the synced views → 4DGS | MIT / no-license code, no gated weights, no human prior [§6.16] | Faithful geometry; benefits directly from more cameras | minutes/clip (est. per §6.9: ~10-30 min) |
| In-the-wild mono camera poses | **MegaSaM** front-end → per-frame extrinsics for the above | Apache-2.0 code (weight-chain license [U], confirm) [§6.18] | Purpose-built for casual dynamic video | 4090-class, seconds |
| Fit + view | **gsplat** (Apache) + our ComfyUI Load/Render/Animate nodes | Apache | — | real-time render |

**Purpose of Layer 0:** validate the product UX, the ComfyUI integration, and demand (waitlist) on the owner's own hardware in days, at ~$0 — the cheap kill-criterion from the §6.12 red-team, now executable locally instead of rented cloud.

**What Layer 0 cannot do:** there is **no released, ungated, single-GPU model that turns a monocular video into a *faithful* 4DGS human in one pass** [§6.16]. LHM fakes the unseen sides; per-video opt needs multiple views. That gap is exactly Layer 1.

## 19.2 Layer 1 — The Light Fine-Tune on Obtainable Data (§6.13 S2, unblocked)

**Architecture**: Flex4DHuman-style — Wan-2.1-1.3B T2V DiT + PRoPE 5-axis positional encoding (full spec in §8.1.1), fine-tuned (LoRA→full-FT hybrid). Downstream 4DGS via gsplat-MCMC (Apache).

**Data (no gating — this is the fix; full audit in §6.17):**

| Dataset | Access | Role | License |
|---|---|---|---|
| **PKU-DyMVHumans** | HF click-through + open Baidu mirror | Dense 56-60 cam, 32 humans / 45 scenarios / 8.2M frames, masks + cam params, 3DGS-ready — **the clean stand-in for DNA-Rendering's dense-GT role** | NC research |
| **CMU Panoptic Studio** | Open `getData.sh`, **no form/email/login** [verified §6.17] | 31 HD + 480 VGA synced cams, multi-person | NC research |
| **AIST++** | Open `downloader.py` | 1,408 seqs × 9 views, dance motion | CC BY 4.0 |
| **THuman2.1 + 2K2K** | Email signed PDF, **no institutional requirement** → solo-passable | ~4,550 renderable scans | research |
| **Self-rendered synthetic** | We own it | MakeHuman CC0 + Anny Apache + CMU/AIST mocap + Poly Haven CC0 + Rocketbox MIT → Blender, unlimited cams, perfect SE(3)/depth/masks | CC0/Apache/MIT |

**Volume check [§6.17]:** >1K genuine multi-view scenes + ~4,550 scans + a 1-3K-scene Blender set (~2.6-13 GPU-days to render on the 96 GB card) — clears the 0.5K-13.6K-scene range used by comparable Wan-class fine-tunes (SynCamMaster 500, ReCamMaster 13.6K), **without any gated data**.

**DISQUALIFIED (do not waste time — institutional email required) [§6.17]:** all ETH-AIT (4D-DRESS, CustomHumans, Hi4D, X-Humans, EMDB), RenderMe-360. DNA-Rendering and ActorsHQ remain OUT per owner directive.

**Machine-time (red-team-audited §6.13, now actually executable):**
- **S1 LoRA smoke** ~1 GPU-day / ~1 week calendar — validates PRoPE conditioning learns (M0.5 pre-gate in §6.14).
- **S2 recommended hybrid** ~7-14 GPU-days / **~5-8 weeks calendar**, expected −2..−4 dB vs the paper (which is also itself less meaningful now: the paper's 25.44 dB anchor was on the gated DNA-Rendering test split, so we re-anchor evaluation to a held-out split of our obtainable data).
- 4DGS fit per clip: ~10-30 min on the same card (§6.9).

**Critical caveat (honest):** quality on PKU-DyMVHumans + CMU Panoptic + synthetic will differ from the paper's DNA-Rendering numbers — different subjects, cameras, calibration. We cannot reproduce their 25.44 dB benchmark (that split is gated); we measure on our own frozen held-out split instead. This is a *re-anchored* target, not a reproduction. The synthetic-to-real domain gap (−1..−3 dB, §6.13 red-team) applies to the synthetic portion of the mix.

## 19.3 Layer 2 — Watch & Upgrade Paths

- **Forge4D** (arXiv 2509.24209) — feed-forward 4D *human* from uncalibrated sparse-view, **Apache code / NC weights** [§6.18]. Closest released analogue to our Quality Mode; evaluate as an alternative to (or initializer for) the Layer-1 fine-tune. Its NC weights are NC-track-only.
- **NoPo4D** (arXiv 2605.22190, May 2026) — unposed feed-forward dynamic Gaussians; **code not yet released** → top watch-item; could simplify the whole front-end if it ships permissively.
- **TrackingWorld** (arXiv 2512.08358, NeurIPS 2025) — does close the moving-camera gap, but NC in practice (chains UniDepth, CoTracker V3, DEVA, Grounded-SAM-2 + an OpenAI API call) [§6.18]. Use only in the NC track; not a commercial front-end.
- **VGGT-1B-Commercial** (Meta) — the only verified commercially-licensed camera/geometry front-end (gated auto-approve, no-military) [§6.18 — confirm exact terms before commercial reliance]; reserve for the commercial Tracks A/B, not needed for this NC MVP.

## 19.4 Recommended Build Sequence (on the owner's machine)

1. **Week 1 — Layer 0 demo.** Install LHM + gsplat + MegaSaM + our ComfyUI nodes on the 96 GB box. Produce one monocular→avatar clip and one 2-8-cam→faithful-4DGS clip. Stand up the waitlist demo. ($0, no training.)
2. **Week 1 parallel — data ingest.** Pull CMU Panoptic (`getData.sh`) + AIST++ (`downloader.py`) immediately (no gate); submit THuman2.1 / ZJU-MoCap signed-PDF requests; start the Blender synthetic render (2.6-13 GPU-days, runs in background between demo work). Click-through PKU-DyMVHumans.
3. **Weeks 2-3 — M0.5 PRoPE pre-gate + S1 smoke** (§6.14): implement PRoPE per §8.1.1, unit-test on synthetic two-view + overfit-one-scene, then LoRA stage-1. Kill-criterion fires on method, not data.
4. **Weeks 3-8 — S2 hybrid fine-tune** on the obtainable mix; eval on frozen held-out split; integrate end-to-end (mono → MegaSaM poses → multi-view gen → gsplat 4DGS → compression → ComfyUI).
5. **Ongoing — Layer 2 watch**; re-evaluate Forge4D as alternative; pull NoPo4D when released.

**Owner-gates (per §6.14):** dataset license click-throughs/PDFs (you sign), and public release. Everything else the goal-mode agent team runs autonomously.
